# 成长赛道报告排版

**NexusAI 子贤学长出品 · 联系方式：HZCK717 · 禁止一切商用。**此为 Skill 来源与使用标识，不自动写入学生的参赛材料。完整条款见安装包根目录 `LICENSE`。

当学生已有报告正文，或 `career-growth-content` 已完成内容初稿，而用户要求 Word、PDF、正式版式或排版优化时使用本技能。先读[版式规范](references/layout-spec.md)。本技能处理视觉组织与文件质量，不改变报告的事实、评分逻辑或学生选择的叙事结构；需要改内容时与 `career-growth-content` 配合。

## 制作与复核

1. 识别标题、开篇、三大部分与子节，让 Word 使用语义段落样式。正文中的证据、个人贡献和反馈仍以原文为准。虚构示范保留醒目标识，不能通过排版把它伪装成真实参赛作品。
2. 对已有 DOCX，可运行 `python scripts/restyle_report.py 输入.docx 输出.docx` 应用本项目的克制型正文版式；原件保留不覆盖。用户要求扉页时，先从学生经历提炼“目标职业—要解决的问题—个人主张”的人物定位，再按[版式规范](references/layout-spec.md)制作单独封面。可用 `--title` 精简过长标题，或在内容适合时用 `--page-break-before "二 成长实践"` 明确分隔页面，但必须看过预览后决定，不能机械套用。确有横向比较价值时，按[虚构表格数据示例](assets/evidence-summary-example.json)提供 `--evidence-json`；只替换成学生真实证据，不复制示例经历。
3. 新建 DOCX 时使用环境可用的文档制作工具，并按版式规范设置 `Title`、一级标题、二级标题、正文、页码；已有段落不应因为换样式而被截断。生成后统计文字与图表，成长赛道正式报告应符合当届官方限制。DOCX 是可编辑稿，正式提交须另行导出并检查 PDF。
4. 每页必须实际预览：先用 Word 或 LibreOffice 导出/渲染，检查标题、中文字体、孤行、跨页标题、表格与页码；可用 DOCX 浏览器预览辅助发现问题，但它不能替代最终 PDF 的页面检查。若本机没有可用渲染器，要明确告知用户该限制，不声称排版已完整验证。
5. 交付 Word 时给出文件，并说明内容是否为示范、是否已完成页面检查。用户还要 PDF 时导出后再次检查文件大小、字数和图表数量。

封面和正文应共享同一套字体、色彩与信息层级；大幅留白必须为职业定位服务，不能遮蔽关键证据。避免花哨渐变、奖牌背景和与职业无关的装饰。
